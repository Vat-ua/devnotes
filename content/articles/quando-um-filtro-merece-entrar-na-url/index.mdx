Nem todo estado precisa viver no mesmo lugar. Um accordion aberto pode desaparecer quando a página recarrega sem causar nenhum problema. Já uma busca que define o que alguém está vendo costuma merecer uma vida um pouco mais longa.

Essa é uma boa pergunta para fazer antes de adicionar mais um `useState`: **esta decisão precisa ser compartilhável, restaurável ou navegável?** Se a resposta for sim, ela provavelmente pertence à URL.

## Três lugares para o estado

Pensar no destino de cada valor evita tanto URLs barulhentas quanto componentes que escondem decisões importantes.

| Tipo de estado | Exemplos | Onde costuma viver |
| --- | --- | --- |
| Local | tooltip aberto, valor de um campo ainda não enviado | componente |
| URL | busca, filtro, ordenação, página atual | query string |
| Servidor | dados remotos, loading, erro, cache | camada de dados |

Não é uma classificação rígida. Ela é apenas uma forma de tornar explícito o que precisa sobreviver além daquele clique.

## A URL é uma interface pública

Quando uma pessoa filtra um catálogo por `Frontend` e ordena por nome, a URL pode registrar essa decisão:

```text
/labs/catalogo-de-ferramentas?category=Frontend&sort=name
```

Esse endereço pode ser recarregado, salvo ou enviado para outra pessoa. O botão de voltar também passa a respeitar a navegação que realmente aconteceu. Em vez de reinventar esse comportamento, o navegador participa do produto.

## Derive a interface a partir dos parâmetros

Os parâmetros não precisam virar uma cópia inteira dos dados no estado. Eles são a intenção; a lista visível continua sendo derivada.

```jsx
const query = searchParams.get("q") ?? "";
const category = searchParams.get("category") ?? "Todos";

const visibleTools = tools
  .filter((tool) => matchesQuery(tool, query))
  .filter((tool) => matchesCategory(tool, category));
```

Ao atualizar um filtro, preserve os parâmetros que não mudaram e remova valores que representam o padrão. Assim, a URL fica curta e continua descrevendo apenas decisões reais.

## Nem tudo deve virar query string

O campo de texto enquanto alguém ainda está digitando pode ser local — especialmente se a busca só for aplicada ao enviar o formulário. Estados efêmeros, como foco, hover e uma mensagem de cópia, também não precisam aparecer no endereço.

Uma boa regra prática: use a URL quando restaurar aquele valor melhora a experiência de uma pessoa que chega depois, volta para trás ou recebe um link.
