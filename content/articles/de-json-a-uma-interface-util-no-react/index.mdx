Uma lista de objetos parece simples até que a interface pede busca, filtros, ordenação e detalhes. A boa notícia é que a maior parte desse trabalho não pede estados complexos — pede separar dados de decisões.

## Guarde a intenção, derive o resultado

Em vez de salvar uma nova lista toda vez que o usuário digita, guarde apenas o que ele escolheu: a busca, o filtro ativo e a forma de ordenação. A lista visível nasce desses valores.

```jsx
const visibleCountries = countries
  .filter(matchesQuery)
  .filter(matchesContinent)
  .toSorted(bySelectedOrder);
```

Esse formato evita que dados de origem e dados filtrados fiquem fora de sincronia. Também deixa cada regra pequena o bastante para testar e explicar.

## Componentes com responsabilidade clara

O campo de busca não precisa conhecer os cards. O card não precisa saber como a lista foi filtrada. Quando cada componente recebe apenas o que precisa, a interface fica mais fácil de evoluir.
