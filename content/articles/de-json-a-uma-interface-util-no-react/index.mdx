Transformar um JSON em interface não é colocar um `map()` na tela. O trabalho começa ao decidir o que é dado de origem, o que é escolha da pessoa e o que pode ser calculado a partir dos dois.

No Lab Explorador de países, `countries` é o dado de origem. O componente guarda somente três escolhas: texto de busca, continente e ordem.

## Guarde os controles, não outra lista

Não salve `filteredCountries` em `useState`. Essa lista já pode ser obtida de `countries`, `query`, `continent` e `sortBy`; mantê-la em dois lugares cria sincronização desnecessária.

```jsx
const filteredCountries = useMemo(() => {
  return countries
    .filter((country) => matchesQuery(country, normalizedQuery))
    .filter((country) => matchesContinent(country, continent))
    .toSorted((first, second) => sortCountries(first, second, sortBy));
}, [normalizedQuery, continent, sortBy]);
```

`toSorted()` devolve uma nova lista. Diferente de `sort()`, ela não altera o array original — uma propriedade importante quando os mesmos dados sustentam mais de uma visão.

## Faça cada filtro uma função pequena

As regras do Lab ficam fora do componente e respondem a uma pergunta cada uma: o texto corresponde? o país pertence ao continente? qual dos dois vem primeiro?

```js
function matchesContinent(country, continent) {
  return continent === 'Todos' || country.continent === continent;
}
```

Isso deixa a combinação de regras legível e permite mudar uma delas sem mexer no rendering dos cards.

## Mantenha os controles controlados

O campo de busca e os selects recebem o valor do estado e notificam apenas a mudança. `FilterBar` não filtra dados nem conhece `countries`; `CountryExplorer` decide o que fazer com as escolhas.

```jsx
<FilterBar
  query={query}
  continent={continent}
  sortBy={sortBy}
  onQueryChange={setQuery}
  onContinentChange={setContinent}
  onSortChange={setSortBy}
/>
```

Essa separação é simples, mas impede que cada controle passe a carregar uma regra diferente de filtragem.

## Mostre detalhes com a semântica certa

O card usa `<details>` e `<summary>` para população e idioma. Para uma abertura e fechamento local, o elemento nativo já entrega comportamento de teclado e informação de estado; não há motivo para criar outro `useState`.

Por fim, trate zero resultados como um estado normal da interface. Uma busca que não encontra países ainda precisa dizer o que aconteceu e sugerir o próximo passo.
