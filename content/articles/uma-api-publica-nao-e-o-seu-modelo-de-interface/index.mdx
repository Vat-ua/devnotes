Uma API pública serve para experimentar `fetch`, mas a resposta dela não deveria definir o formato dos seus componentes. Ela é o contrato do serviço; a interface precisa de um contrato próprio.

No Lab de personagens, por exemplo, a API entrega URLs, objetos aninhados e uma lista de episódios. O card só precisa de nome, status, origem, total de episódios e imagem.

## Traduza a resposta antes de renderizar

Converta os dados na função que faz o request. Assim, o restante da aplicação trabalha com um objeto pequeno e previsível.

```js
function toCharacter(apiCharacter) {
  return {
    id: apiCharacter.id,
    name: apiCharacter.name,
    status: apiCharacter.status,
    species: apiCharacter.species,
    origin: apiCharacter.origin.name,
    episodeCount: apiCharacter.episode.length,
    image: apiCharacter.image,
  };
}
```

Se a API trocar `origin.name` por outra estrutura, você corrige a adaptação em um lugar. `CharacterCard` não precisa saber que esses dados vieram de uma API externa.

## Cancele a busca que deixou de ser atual

Uma pessoa pode digitar uma nova busca antes de a anterior terminar. Sem cancelamento, uma resposta antiga pode atualizar a tela depois da busca mais recente.

O Lab cria um `AbortController` para cada efeito e ignora o erro esperado do cancelamento:

```jsx
useEffect(() => {
  const controller = new AbortController();

  fetchCharacters({ query: query.trim(), status, signal: controller.signal })
    .then(({ characters, nextPage }) => {
      setCharacters(characters);
      setNextPage(nextPage);
      setState(characters.length === 0 ? 'empty' : 'ready');
    })
    .catch((error) => {
      if (error.name !== 'AbortError') setState('error');
    });

  return () => controller.abort();
}, [query, status]);
```

## Uma lista vazia não é um erro

Na Rick and Morty API, uma busca sem resultados responde com `404`. Para a interface, isso significa uma lista vazia — não uma falha de conexão.

```js
if (response.status === 404) {
  return { characters: [], nextPage: null };
}
```

Vale deixar explícitos quatro estados: carregando, com resultados, vazio e erro. Cada um pede uma mensagem diferente; misturá-los torna a tela confusa e dificulta recuperar de um problema real.

## Deixe a API em uma borda pequena

Concentre URL, parâmetros, erros HTTP e adaptação em `fetchCharacters`. Dessa forma, trocar o endpoint, adicionar autenticação ou testar a tela com dados locais não exige reescrever os componentes.
