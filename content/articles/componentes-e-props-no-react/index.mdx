Uma interface costuma repetir estruturas. Imagine uma página que apresenta algumas ferramentas:

```jsx
<div className="tool-card">
  <h2>React</h2>
  <p>Biblioteca para construir interfaces.</p>
</div>

<div className="tool-card">
  <h2>Vite</h2>
  <p>Ferramenta para desenvolvimento frontend.</p>
</div>
```

Os dois blocos têm a mesma estrutura. O que muda são os dados. No React, podemos transformar essa parte repetida em um componente e reutilizá-la.

## Componentes: uma estrutura reutilizável

Um componente React pode ser uma função JavaScript que retorna `JSX`:

```jsx
function ToolCard() {
  return (
    <div className="tool-card">
      <h2>React</h2>
      <p>Biblioteca para construir interfaces.</p>
    </div>
  );
}
```

Depois podemos usá-lo como parte da interface:

```jsx
function App() {
  return (
    <div>
      <ToolCard />
    </div>
  );
}
```

`ToolCard` parece uma tag HTML, mas é um componente criado pela aplicação. Em React, nomes de componentes customizados sempre começam com letra maiúscula.

Ainda existe um problema: esse componente sempre mostra "React". Para reutilizar a mesma estrutura com conteúdos diferentes, precisamos passar dados para ele. É aí que entram as props.

## Props: dados que configuram o componente

Para que o mesmo componente mostre conteúdos diferentes, podemos informar os dados quando usamos o componente:

```jsx
function App() {
  return (
    <div>
      <ToolCard name="React" description="Biblioteca para construir interfaces." />
      <ToolCard name="Vite" description="Ferramenta para desenvolvimento frontend." />
    </div>
  );
}
```

Nesse exemplo, `App` é o componente pai e cada `ToolCard` é um componente filho. O pai envia os dados, e o filho usa esses dados para decidir o que renderizar.

Os valores enviados chegam ao componente em um objeto chamado `props`. Props são dados de entrada do componente: ele pode usá-las para construir a interface, mas não deve modificar os valores recebidos. Podemos acessar `props.name` e `props.description`, mas é comum desestruturar as propriedades diretamente nos parâmetros da função:

```jsx
function ToolCard({ name, description }) {
  return (
    <div className="tool-card">
      <h2>{name}</h2>
      <p>{description}</p>
    </div>
  );
}
```

Assim, a estrutura de `ToolCard` continua a mesma, enquanto o conteúdo pode mudar a cada uso.

### Props opcionais e valores padrão

Uma prop pode ter um valor padrão. Aqui, `featured` será `false` quando não for informada:

```jsx
function ToolCard({ name, description, featured = false }) {
  return (
    <div className="tool-card">
      {featured && <span className="badge">Destaque</span>}
      <h2>{name}</h2>
      <p>{description}</p>
    </div>
  );
}

<ToolCard
  name="React"
  description="Biblioteca para construir interfaces."
  featured
/>;
```

Escrever `featured` equivale a `featured={true}`.

## De um array para vários componentes

Em aplicações reais, os dados muitas vezes estão organizados em arrays de objetos:

```jsx
const tools = [
  {
    id: 'react',
    name: 'React',
    description: 'Biblioteca para construir interfaces.',
    featured: true,
  },
  {
    id: 'vite',
    name: 'Vite',
    description: 'Ferramenta para desenvolvimento frontend.',
    featured: false,
  },
];
```

Podemos transformar esse array em componentes usando o método `.map()`:

```jsx
function App() {
  return (
    <div>
      {tools.map((tool) => (
        <ToolCard
          key={tool.id}
          name={tool.name}
          description={tool.description}
          featured={tool.featured}
        />
      ))}
    </div>
  );
}
```

O `.map()` percorre o array e, para cada objeto, retorna um novo `ToolCard`. Os dados de cada ferramenta são passados ao componente por meio das props. Esse padrão aparece o tempo todo em React: **dados → .map() → componentes → props → interface**.

### Por que usamos `key`?

Ao renderizar uma lista, o React precisa identificar cada elemento entre uma renderização e outra. Para isso, cada componente da lista recebe uma `key` estável e única entre seus elementos irmãos. No exemplo anterior, usamos `key={tool.id}` porque `id` vem dos próprios dados e identifica cada ferramenta.

Em uma lista fixa, que não será reordenada nem terá itens adicionados ou removidos, o índice também pode ser usado:

```jsx
const steps = ['Dados', 'Componentes', 'Interface'];

function Flow() {
  return (
    <ol>
      {steps.map((step, index) => (
        <li key={index}>{step}</li>
      ))}
    </ol>
  );
}
```

Nesse caso, a posição de cada item permanece estável. Se a lista puder mudar, prefira um identificador dos próprios dados, porque o índice pode passar a representar outro item. Também não gere a `key` durante a renderização com valores como `Math.random()`: ela mudaria a cada vez.

A `key` é usada pelo próprio React e não chega ao componente como uma prop. Se `ToolCard` também precisar do identificador, passe outro nome explicitamente, como `toolId={tool.id}`.

## children: conteúdo dentro de componentes

Até agora, cada `ToolCard` foi renderizado diretamente dentro de uma `div`. Podemos também criar um componente responsável apenas por organizar os cards de forma visual:

```jsx
function ToolGrid({ children }) {
  return <div className="tool-grid">{children}</div>;
}
```

Agora podemos usar esse componente como contêiner:

```jsx
function App() {
  return (
    <ToolGrid>
      {tools.map((tool) => (
        <ToolCard
          key={tool.id}
          name={tool.name}
          description={tool.description}
          featured={tool.featured}
        />
      ))}
    </ToolGrid>
  );
}
```

Tudo o que aparece entre a tag de abertura `<ToolGrid>` e a de fechamento `</ToolGrid>` chega ao componente através da prop especial `children`.

Nesse caso, o `ToolGrid` não precisa saber quantas ferramentas existem nem quais dados elas recebem. Sua responsabilidade é apenas definir o layout da lista. Esse padrão é chamado de **composição**: componentes menores são combinados para formar partes maiores da interface.

## Em resumo

Para fixar o modelo mental de como o React estrutura a interface:

- **Componentes de função** são funções JavaScript que descrevem uma parte da interface e são usadas no JSX com nomes iniciados por letra maiúscula.
- **Props** são dados recebidos pelo componente e usados para configurar o que ele renderiza.
- **Fluxo dos dados:** O componente pai passa props para o componente filho.
- **Listas:** Use `.map()` para transformar arrays de dados em componentes e forneça uma `key` estável para cada item.
- **Composição:** Use a prop `children` para criar componentes de layout ou contêineres flexíveis.
