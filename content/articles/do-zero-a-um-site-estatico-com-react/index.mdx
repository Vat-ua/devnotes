Um site estático não precisa ser um arquivo HTML enorme nem uma aplicação React com camadas demais. Para um projeto pequeno, o objetivo é simples: ter uma estrutura que seja fácil de entender hoje e fácil de ampliar quando uma nova página aparecer.

Neste guia, vamos criar uma base com três páginas: **Início**, **Serviços** e **Sobre**. O resultado é estático, mas as rotas continuam sendo páginas reais da aplicação.

## 1. Crie o projeto com Vite

Comece com o template React em JavaScript e instale apenas o roteador. Não há necessidade de biblioteca de componentes ou framework de CSS para esta base.

No terminal, na pasta onde você guarda seus projetos, execute:

```bash
# terminal
pnpm create vite meu-site --template react
cd meu-site
pnpm install
pnpm add react-router
pnpm dev
```

O Vite entrega o servidor local, o build de produção e uma configuração pequena. Antes de mudar qualquer arquivo, abra a URL mostrada no terminal e confirme que o projeto inicial funciona.

## 2. Dê nomes claros às responsabilidades

Crie uma estrutura suficiente para diferenciar páginas, componentes compartilhados e estilos. Não crie uma pasta para cada ideia hipotética.

Ao final desta etapa, a pasta `src/` terá esta organização:

```text
# src/
src/
  components/
    Header.jsx
    Footer.jsx
  layouts/
    AppLayout.jsx
  pages/
    home.jsx
    servicos.jsx
    sobre.jsx
  styles/
    global.css
  App.jsx
  main.jsx
```

Uma página representa uma rota. Um componente compartilhado existe porque aparece em mais de um lugar. Um layout junta a moldura que todas as páginas dividem.

## 3. Inicialize o router

No ponto de entrada, envolva a aplicação com `BrowserRouter`. Em um host estático, lembre-se de configurar fallback para `index.html` quando for publicar; durante o desenvolvimento, o Vite já cuida disso.

Substitua o conteúdo de `src/main.jsx`:

```jsx
// src/main.jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { BrowserRouter } from "react-router";
import App from "./App.jsx";
import "./styles/global.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </StrictMode>,
);
```

## 4. Declare as páginas em um só lugar

`App.jsx` deve explicar a navegação sem esconder o mapa do site. O `AppLayout` envolve as páginas e renderiza cada uma na posição de `Outlet`.

Substitua o conteúdo de `src/App.jsx`:

```jsx
// src/App.jsx
import { Route, Routes } from "react-router";
import AppLayout from "./layouts/AppLayout.jsx";
import Home from "./pages/home.jsx";
import Servicos from "./pages/servicos.jsx";
import Sobre from "./pages/sobre.jsx";

export default function App() {
  return (
    <Routes>
      <Route element={<AppLayout />}>
        <Route index element={<Home />} />
        <Route path="servicos" element={<Servicos />} />
        <Route path="sobre" element={<Sobre />} />
      </Route>
    </Routes>
  );
}
```

Crie uma primeira versão para cada página importada pelas rotas:

```jsx
// src/pages/home.jsx
export default function Home() {
  return <main><h1>Home</h1></main>;
}
```

```jsx
// src/pages/servicos.jsx
export default function Servicos() {
  return <main><h1>Serviços</h1></main>;
}
```

```jsx
// src/pages/sobre.jsx
export default function Sobre() {
  return <main><h1>Sobre</h1></main>;
}
```

## 5. Compartilhe a moldura, não o conteúdo

Header e Footer são partes da estrutura do produto; o conteúdo de cada página continua local à sua rota. Esse limite deixa a aplicação previsível.

Crie `src/layouts/AppLayout.jsx`:

```jsx
// src/layouts/AppLayout.jsx
import { Outlet } from "react-router";
import Header from "../components/Header.jsx";
import Footer from "../components/Footer.jsx";

export default function AppLayout() {
  return (
    <div className="app-shell">
      <Header />
      <Outlet />
      <Footer />
    </div>
  );
}
```

No Header, use `NavLink` em vez de links soltos: ele permite identificar a rota ativa sem manter outro estado apenas para isso.

Crie `src/components/Header.jsx`:

```jsx
// src/components/Header.jsx
import { NavLink } from "react-router";

const navigation = [
  ["Início", "/"],
  ["Serviços", "/servicos"],
  ["Sobre", "/sobre"],
];

export default function Header() {
  return (
    <header>
      <NavLink to="/">Meu site</NavLink>
      <nav aria-label="Principal">
        {navigation.map(([label, to]) => (
          <NavLink key={to} to={to}>{label}</NavLink>
        ))}
      </nav>
    </header>
  );
}
```

Crie também `src/components/Footer.jsx`, usado pelo layout:

```jsx
// src/components/Footer.jsx
export default function Footer() {
  return <footer>Meu site</footer>;
}
```

## 6. Comece o CSS pelo sistema, não pela página

Defina primeiro cores, largura do container, tipografia, foco e espaçamentos globais. Depois cada página pode compor essas regras, sem criar uma paleta nova por seção.

Crie `src/styles/global.css`:

```css
/* src/styles/global.css */
:root {
  --bg: #f5f3ed;
  --surface: #fffefa;
  --text: #151614;
  --muted: #6e6d66;
  --line: rgba(21, 22, 20, 0.15);
  --container: 1180px;
  font-family: system-ui, sans-serif;
}

body {
  margin: 0;
  background: var(--bg);
  color: var(--text);
}

:focus-visible {
  outline: 3px solid rebeccapurple;
  outline-offset: 4px;
}
```

Para a navegação mobile, prefira começar com uma coluna e abrir um menu com um botão semântico. Só adicione o comportamento de menu quando os links realmente não couberem; responsividade não precisa significar complexidade antecipada.

## 7. Dê conteúdo às páginas sem criar uma camada de dados

Um site com três páginas institucionais não precisa de coleção, CMS ou arquivo de dados. O conteúdo pode viver diretamente em cada página enquanto ainda for simples.

Substitua o conteúdo de `src/pages/servicos.jsx` por uma seção semântica:

```jsx
// src/pages/servicos.jsx
export default function Servicos() {
  return (
    <main>
      <h1>Serviços</h1>
      <section>
        <h2>Estratégia, design e desenvolvimento</h2>
        <p>
          Ajudamos equipes a transformar uma ideia em uma experiência digital clara.
        </p>
      </section>
    </main>
  );
}
```

Se o site crescer e passar a ter muitos serviços, cases ou artigos, aí faz sentido introduzir dados locais ou arquivos de conteúdo. A rota e o layout não precisam mudar para isso.

## 8. Faça o build antes de considerar pronto

O servidor de desenvolvimento é ótimo para trabalhar, mas o build confirma que imports, rotas e assets podem ser entregues como arquivos estáticos.

No terminal, na raiz do projeto, execute:

```bash
# terminal
pnpm run build
pnpm run preview
```

Abra Início, Serviços e Sobre no preview. Teste também uma rota acessada diretamente e a navegação em uma tela estreita. Esse pequeno ritual encontra problemas que um componente isolado não mostra.
